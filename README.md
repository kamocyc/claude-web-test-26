# Smooth World

ゲームシステムは Minecraft ライクだが、**見た目にボクセル感が一切ない完全スムーズな地形**の
ブラウザゲーム。TypeScript + three.js + Vite。

- 無限に広がる地形をシードから生成し、リアルタイムでストリーミング
- 球ブラシで掘る／盛る（穴は常に真円で滑らか）
- 一人称の移動・衝突・ジャンプ・飛行・遊泳
- **バイオーム**（草原・森・砂漠・ツンドラ・山岳）と、**川と湖**、**険しい山と断崖**
- **木**（広葉樹・針葉樹・サボテン）。幹には当たり判定がある
- **村**（家・大広間・小屋・井戸・見張り台と、広場から伸びる土の道）
- 素材（草／土／岩／砂）のホットバー
- 海面と水中表現、昼夜サイクル
- 編集差分は IndexedDB に保存され、リロードしても残る

## なぜボクセルに見えないのか

ワールドの実体はブロックの配列ではなく、**連続な密度場** `density(x, y, z)` である
（`> 0` が固体）。これを **Surface Nets** で等値面として取り出す。

| 課題 | 手法 |
| --- | --- |
| 段差の排除 | 符号が混在するセルごとに 1 頂点を置き、位置をエッジ交差点の平均にする（`surfaceNets.ts`） |
| 滑らかな陰影 | 法線は密度場の勾配（中央差分）を三線形補間して求める。面法線を使わないのでファセットが出ない |
| チャンクの継ぎ目 | 各チャンクは格子 `[-2, 32+2]` をサンプルし、セル `[-1, 32)` を生成する。隣接チャンクは同じ密度関数から同じコーナー値を得るので、境界の頂点は数値的に完全一致する |
| UV が存在しない | ワールド座標の**三面投影**でテクスチャを貼る。テクスチャは起動時に CPU で生成するタイリングノイズで、外部アセットは不要（`proceduralTextures.ts` / `TerrainMaterial.ts`） |
| 素材の境界 | 頂点属性を素材 ID ではなく **4 成分の重み** `matw` にして GPU 補間させる |
| 編集の丸さ | ブラシを符号付き距離場として合成する。設置 `d = max(d, r - dist)` / 掘削 `d = min(d, dist - r)`。何度掛けても発散せず常に真球（`edits.ts`） |

## 地形の作り方

`world/density.ts` の `baseHeight()` が 2D の高度場を、`density()` が 3D の肉付けを担当する。

- **ドメインワープ**した大陸ノイズを実効レンジで正規化し、陸と海がほぼ半々になるようにする
- **山岳マスク × 尾根ノイズ²** で鋭い山を作り、二次尾根で断崖と段丘を重ねる
- **バイオーム**は気温・湿度の 2 つの低周波ノイズ。丘の振幅、砂丘、素材、木の種類と密度、
  シェーダの草の色と雪線がすべてこれで変わる
- **川**は尾根ノイズのゼロ交差線（`1 - |noise| / 幅`）に沿って地形を海面下まで引き下げる。
  **湖**は低地の窪みを同様に海面下へ沈める。海面は一枚の平面なので、`y < 0` を彫れば自動的に水が入る
- **オーバーハングと洞窟**は地表付近と地中だけで 3D ノイズを効かせる（`density()`）

## 木と村

**木**（`world/vegetation.ts`）は Worker がメッシュ化した直後に、**上向きの頂点**をそのまま
足場として選ぶ。4.6 m 格子のセルごとに 1 本までとし、置くかどうか・種類・大きさは
セル座標のハッシュだけで決まるので、再メッシュしても同じ場所に戻る。
地面を掘って頂点が消えれば木も消える。描画は種類ごとの `InstancedMesh`、
幹は垂直円柱として当たり判定に使う。

**村**（`world/village.ts`）は 420 m グリッドのセルごとに決定論的に生成する。
セル内で数か所試し、海の中・山の上・起伏が大きすぎる場所を避けて敷地を決める。
敷地は密度場の側で平坦化する — `height()` が地形を敷地高さへブレンドし、
同時に 3D のオーバーハングと洞窟も抑えるので、建物が乗る本当に平らな地面になる。
建物の壁は `buildingBoxes()` が返す軸平行ボックスで、**描画も当たり判定も同じ配列**を使う。
ドアの位置だけ壁を分割して開口にしてあるので、見た目どおりに出入りできる。

## 移動と当たり判定

カプセルの軸上の数点をサンプルし、`密度 / |勾配|` を符号付き距離の近似として
勾配方向へ押し出す（`player/Player.ts`）。地形が滑らかなので、ブロック地形のような
「段差を登る」特別処理は要らない。

接地判定は押し出しの副作用ではなく**足元への独立したプローブ**で行う。これが重要で、
- 接地中は重力を溜めない → 押し出しベクトルの水平成分で斜面をずり落ちない
- 入力が無いときは強い制動＋停止しきい値をかける → 坂で立ち止まれる
- 下り坂では純粋な鉛直補正で地面へ吸着させる → 滑らずに地形へ追従する

## 構成

```
src/
  main.ts                      ブートストラップとゲームループ
  engine/Renderer.ts           WebGLRenderer / scene / camera / fog
  engine/SkyDayNight.ts        空シェーダ・太陽・星・環境光
  engine/Water.ts              海面（頂点シェーダで波と法線）
  world/noise.ts               シード付き Perlin / Simplex / fBm / ridged
  world/density.ts             密度場・バイオーム・川と湖・素材
  world/surfaceNets.ts         等値面抽出（このプロジェクトの心臓部）
  world/village.ts             村のレイアウトと壁のボックス（純粋関数）
  world/vegetation.ts          木の配置
  world/World.ts               チャンク管理・ストリーミング・密度サンプリング・編集
  world/VillageManager.ts      周囲の村の生成と破棄
  world/chunk.worker.ts        生成＋メッシュ化を行う Worker
  world/WorkerPool.ts          優先度付きジョブキュー
  world/edits.ts               球ブラシ
  world/storage.ts             IndexedDB（編集差分とメタ情報）
  render/TerrainMaterial.ts    MeshStandardMaterial + 三面投影 + バイオーム着色
  render/proceduralTextures.ts CPU 生成のタイリングノイズ
  render/treeMeshes.ts         木のプロトタイプ形状
  render/villageBuilder.ts     建物のジオメトリと当たり判定ボックス
  player/                      入力・物理・レイマーチ
  ui/hud.ts                    HUD
```

密度は**メインスレッドに一切保持しない**。衝突判定やレイキャストが必要とする点で
解析的に評価し、編集差分を上書きして三線形補間する（`World.sample`）。
Worker が作るメッシュと完全に同じ場を参照できるうえ、メモリ使用量はゼロ。
2D の高度成分は列単位でキャッシュされる。

## 主な調整パラメータ

| 値 | 場所 | 意味 |
| --- | --- | --- |
| `VIEW_DISTANCE` | `main.ts` | 描画距離（チャンク数）。既定 7 = 224 m |
| `CHUNK_SIZE` / `VOXEL_SIZE` | `world/constants.ts` | チャンクの分割数と 1 セルの大きさ |
| `VILLAGE_CELL` | `world/constants.ts` | 村を配置するグリッドの間隔（既定 420 m） |
| `SEA_LEVEL` / `CAVE_MIN_Y` | `world/constants.ts` | 海面の高さ、洞窟の下限 |
| `DensityField.baseHeight()` | `world/density.ts` | 大陸・山・丘・川・湖の形状 |
| `planCell()` | `world/vegetation.ts` | バイオームごとの木の密度と種類 |
| `dayLength` | `engine/SkyDayNight.ts` | 1 日の実時間（秒）。既定 900 |

## デバッグフック

`window.__smooth` から状態の確認と操作ができる（自動テストでも使っている）。

```js
__smooth.state()          // 座標・接地・地面の法線 y・付近の幹と壁の数
__smooth.teleport(x, z)   // その座標の地表へ移動
__smooth.gotoVillage()    // 最寄りの村の広場へ移動して広場を向く
__smooth.look(yaw, pitch) // 視線角を直接設定
__smooth.loaded / .desired / .trees / .villages
```

## テスト

`npm test`（vitest）は等値面抽出と村レイアウトの正しさを検証する。

- 球の密度場から抽出した全頂点が半径の上に乗る（誤差 < 0.12 — ボクセル表現なら 0.5 前後になる）
- 頂点法線が解析的な外向き法線と一致する（内積 > 0.985）
- 全三角形の巻き順が外向き（裏面が出ない）
- **隣接チャンクを独立にメッシュ化しても境界の頂点が完全一致する**（継ぎ目が出ない証明）
- 球ブラシが冪等で、掘る↔盛るを往復しても密度が発散しない
- 村が決定論的に生成され、建物どうしが重ならず、**ドアの位置に開口がある**

`npm run test:e2e`（Playwright）は実際にブラウザで動かす。

- 視界内チャンクが全てメッシュ化され、描画が継続し、掘削がワールドに反映される
- **WASD がカメラの向きどおりに動く**（前後・左右の取り違えの回帰テスト）
- **入力を離すと止まり、斜面でも 0.2 m 以上滑らない**（滑りの回帰テスト）
- 村が生成され、壁の当たり判定を持ち、木が生えている

ヘッドレス環境は SwiftShader（CPU ラスタライザ）なので数 fps しか出ない。
フレームレートの測定ではなくフリーズ検出が目的で、物理も 1 フレームあたりの
サブステップ上限で頭打ちになるため、移動テストは距離ではなく向きを見ている。
